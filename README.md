# 📚 Dictionary-Sözlük: Software Architecture and Approaches Archive

This project is created to compile and explain the **methods, architectural patterns, software principles, and tools** I encounter during the software development process.

Its main purpose is not to deliver a runnable application but to document how to **make correct technical decisions**, **compare architectures**, and understand **which technologies to use and how in different scenarios**.

---

## 🎯 Project Purpose

- To document software architectures, layered structures, SOLID principles, dependency management, and related topics with examples  
- To provide explanatory content on tools, libraries, and approaches used in .NET-based projects  
- To reference the foundational principles behind the technical choices I apply in my own projects  
- To create a continuously updated technical reference source that can guide other developers  

---

## 🧭 What’s Inside This Repository?

- Explanations of common software architectures (Layered Architecture, Clean Architecture, Hexagonal, DDD, etc.)  
- Software design principles such as SOLID, DRY, KISS, YAGNI, and others  
- Notes on frequently used .NET libraries and tools (MediatR, EF Core, AutoMapper, FluentValidation, etc.)  
- Example explanations of common design patterns used in architecture (Repository, Service, Factory, Decorator, etc.)  
- Approaches to cross-cutting concerns like Logging, Exception Handling, Dependency Injection / IoC  
- Summaries about Microservices architectures and Event-Driven designs  

---

## 📌 How to Use This?

This project is not a runnable application.

However:

- I reference the explanations in this repository in other projects I develop  
- I document architectural decisions I face during development here to create **reusable knowledge**  
- Whenever I start a new project, I note down the answer to “Why did I choose this approach?”  
- I aim to help others understand and apply these approaches in their own projects  

---

## ✍️ Who Is This Useful For?

- Developers looking for practical and applicable explanations about software architectures  
- Those who want to contribute to architectural decision-making processes in .NET projects  
- Intermediate and advanced developers aiming to build solid and maintainable technical foundations in their projects  

---

## 🔄 A Continuously Evolving Resource

This repository is not static.  
It is **continuously updated** with new insights about technologies, libraries, and architectural patterns I learn.  
It aims to be a current and reliable reference point for both myself and others.
